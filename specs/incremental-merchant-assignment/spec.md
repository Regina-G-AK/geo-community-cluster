# 新商户增量归属

## Overview

- 本功能用于在算法一初始聚类和人工定稿后，将待判定新商户按观察证据、图邻居、地理位置和客群重叠归入已有商圈。
- 本次实现覆盖算法二的新商户增量归属主路径，不实现月度局部 Leiden 新商圈发现旁路。
- 初始商圈和 SPPMI 边权读取 `algorithm_one_output/sppmi_leiden_260622154451/` 下的算法一结果。
- 观察池、商圈档案、判定结果、人工工单和增量实验记录先落为本地文件，为后续写入 Hive 保留清晰的数据边界。

## Requirements

- 系统 MUST 在 `business_district` 目录外新建独立代码目录承载增量更新实现。
- 系统 MUST 接收待判定商户输入表，输入表 MUST 至少提供商户 ID、城市、首次观察日期、观察期交易或客群证据；若地理分数需要参与计算，输入表 MUST 提供经纬度字段。
- 系统 MUST 从算法一输出读取 `communities.csv`、`merchants.csv`、`edges.csv` 和 `summary.json` 作为固定层初始数据。
- 系统 MUST 使用算法一 `edges.csv` 中的 SPPMI 结果计算新商户与存量商户的图分数，不得在本次实现中重新跑全量初始聚类。
- 系统 MUST 支持观察池文件持久化，并记录商户、城市、首次出现时间、最近观察时间、去重持卡人数、观察天数、最近判定状态、最近分数和原因。
- 系统 MUST 使用 `min_observation_days=28` 和 `min_unique_users=5` 作为参与判定的初始证据阈值。
- 证据不足的新商户 MUST 保持在观察池，判定状态写为继续观察。
- 系统 MUST 计算图分数、地理分数和客群分数。
- 图分数 MUST 按新商户 top-k SPPMI 邻居对已有商圈标签进行加权投票，锚点商户票权 MUST 支持乘以锚点权重。
- 地理分数 MUST 使用新商户到候选商圈锚点集的最近距离和商圈地理尺度计算高斯核分数。
- 新商户无坐标或候选商圈缺少可用锚点坐标时，系统 MUST 将地理权重按比例分摊给图分数和客群分数。
- 客群分数 MUST 使用精确 Jaccard 相似度计算，不使用 MinHash 或 HyperLogLog。
- 冷启动融合权重 MUST 使用图分数 0.6、地理分数 0.3、客群分数 0.1。
- 系统 MUST 提供可配置的归入绝对阈值 `theta` 和归入差值阈值 `delta`，初始值 SHOULD 分别设为 `0.55` 和 `0.10`。
- 当最高融合分数不低于 `theta` 且与次高融合分数差值不低于 `delta` 时，系统 MUST 将新商户自动归入最高分商圈。
- 当最高融合分数低于 `theta` 时，系统 MUST 将新商户继续留在观察池。
- 当最高分与次高分差值低于 `delta` 时，系统 MUST 生成人工工单。
- 当图分最高商圈与地理分最高商圈不同且地理分数参与计算时，系统 MUST 生成人工工单。
- 人工工单 MUST 写入 `manual_review.csv`，并包含商户、城市、候选商圈、融合分数、图分数、地理分数、客群分数、触发原因、观察天数和去重持卡人数。
- 自动归入成功后，系统 MUST 同步更新商圈档案中的成员集合、归属置信度、客群摘要和地理轮廓。
- 商圈档案输出 MUST 保留算法一原始商圈 ID，不得重编号已有商圈。
- 系统 MUST 新增独立的增量实验记录文档，并在每次增量运行结果成功落盘后追加运行记录。
- 增量实验记录 MUST 包含运行时间、输入数据来源、算法一结果目录、完整参数快照、判定统计、人工工单统计、观察池统计和总耗时。
- 本次实现完成后 MAY 不运行端到端验证，但代码结构 SHOULD 保留后续命令行入口和测试入口。
- 系统 MUST 使用明确错误处理；当必需输入文件、必需字段或关键参数缺失时 MUST 抛出清晰错误，不得静默跳过。

## Design

- 新代码目录命名为 `incremental_assignment`，内部按配置、数据模型、输入加载、打分、判定、档案更新、输出写入和运行入口拆分模块。
- 配置模型集中定义算法一输出目录、待判定商户输入表、输出目录、观察池路径、商圈档案路径、人工工单路径、增量实验记录路径和全部阈值参数。
- 数据模型使用严格类型表达商户、商圈档案、SPPMI 边、观察池记录、三类分数、判定结果和人工工单。
- 输入加载器负责校验算法一输出表字段，并把 `merchants.csv` 中的 `is_anchor_candidate` 作为初始锚点标记。
- 图分数模块从 SPPMI 边表中筛选新商户相关边，按城市和 top-k 邻居计算商圈投票比例。
- 地理分数模块从商圈档案中的锚点坐标和地理尺度计算高斯核；缺失坐标能力时返回不可用状态，由融合模块处理权重分摊。
- 客群分数模块读取新商户持卡人集合和商圈客群集合，使用精确集合交并比计算 Jaccard。
- 融合模块只做单一加权融合，不引入 GBDT 或逻辑回归；监督模型替代手工权重留作后续扩展。
- 判定模块输出三态结果：自动归入、继续观察、送人工。
- 档案更新模块只对自动归入结果更新固定层派生文件，并保留原始算法一结果目录不变。
- 输出目录采用单次运行独立目录，避免覆盖历史增量结果。
- 增量实验记录写入新的文档，例如 `docs/incremental_experiments.md`，不混写算法一聚类实验记录。
