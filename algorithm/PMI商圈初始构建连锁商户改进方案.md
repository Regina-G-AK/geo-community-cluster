# PMI 商圈初始构建的连锁商户改进方案

## 背景

`商圈构建算法设计0613.md` 中的初始构建方案，核心链路是线上商户识别、交易对生成、PMI/SPPMI 建图、互为 top-k 稀疏化、迭代 hub 清洗、Leiden 社区发现和锚点确认。该方案默认图节点已经是可代表线下实体的商户。

远程实验暴露了一个新的风险：大量连锁门店使用同一个商户名称。如果图节点直接使用商户名称，同名门店会被错误合并成一个超级节点。此时 PMI 只能看到已经合并后的高频节点，无法再区分不同地点的真实门店，容易出现以下问题：

- 同一品牌跨城市、跨商圈的交易被汇总到同一个节点。
- 该节点会连接多个真实商圈，形成类似线上商户的桥接 hub。
- PMI 可能无法有效压低它，因为每个真实门店在本地都有真实共现，合并后会把多个局部强信号叠加。
- Leiden 会被同名品牌节点粘连，导致多个商圈被错误合并。
- 锚点选择可能误把高客流连锁品牌选为中心，降低商圈身份稳定性。

因此新方案不把连锁识别放在 PMI 之后补救，而是在 PMI 之前增加“门店实体化 + 品牌识别”层。PMI 继续作用于门店级节点，品牌只作为诊断、降权和质量校验字段。

## 核心原则

1. **图节点必须是门店实体，不是商户名称。**
   - `merchant_node_id` 表示一个尽可能接近物理地点的门店。
   - `brand_id` 表示规范化后的品牌或同名商户组。
   - 同名但位于不同地点、不同城市、不同局部客群网络的商户必须拆成不同节点。

2. **PMI 不负责修复错误合并的节点。**
   - PMI 能压低“随机和很多人共现”的 hub。
   - PMI 不能把已经按名称合并的多个真实门店重新拆开。
   - 节点粒度错误必须在建图前修正。

3. **连锁商户不是一律剔除，而是门店级保留、品牌级约束。**
   - 本地门店仍然可能是商圈成员。
   - 品牌整体不应成为跨商圈桥梁。
   - 同一品牌的多门店信号要用于识别风险，而不是直接作为空间邻近证据。

## 改进后的整体流程

```plain
原始交易
  → 商户主数据标准化
  → 品牌识别与同名簇生成
  → 门店实体拆分
  → 线上商户识别
  → 到访事件合并
  → 门店级交易对生成
  → 门店级 PMI/SPPMI
  → 品牌感知边权修正
  → 互为 top-k 稀疏化
  → 迭代 hub 与品牌桥接清洗
  → Leiden 社区发现
  → 连锁风险质量校验
  → 锚点候选生成
```

与原方案相比，新增的关键环节是：

- PMI 前新增“品牌识别与门店实体拆分”。
- PMI 后新增“品牌感知边权修正”。
- 迭代清洗阶段新增“品牌桥接节点”识别。
- 质量校验新增连锁覆盖率、同名分散度和可疑社区指标。

## 一、商户主数据标准化

先对原始商户字段做标准化，输出两类字段：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `raw_merchant_id` | 原始商户号 | 追溯原始交易 |
| `raw_name` | 原始商户名称 | 保留审计 |
| `normalized_name` | 清洗后的名称 | 品牌识别 |
| `brand_id` | 品牌或同名组 ID | 连锁识别、品牌降权 |
| `merchant_node_id` | 门店级节点 ID | 建图节点 |
| `store_evidence` | 门店拆分证据 | 人工复核 |
| `entity_confidence` | 实体置信度 | 低置信度进入灰区降权 |

名称标准化只用于品牌归并，不用于图节点归并。标准化规则包括：

- 去除公司后缀、收单渠道后缀、支付机构后缀。
- 统一全角半角、大小写、空格、标点。
- 保留分店名、商场名、路名、城市名等位置线索。
- 对“星巴克国贸店”“星巴克(国贸店)”这类名称拆出 `brand_id=星巴克` 和 `store_hint=国贸店`。

如果已有稳定的门店 ID、POI ID、终端 ID、清算商户号和地址，优先使用这些字段构造门店实体。没有这些字段时，才用交易网络和辅助地理数据推断。

## 二、品牌识别与同名簇生成

对每个 `normalized_name` 或品牌候选组计算连锁风险特征：

| 特征 | 解释 | 连锁风险信号 |
| --- | --- | --- |
| 同名实体数 | 同名原始商户号数量 | 数量越多越像连锁 |
| 城市分布熵 | 按持卡人常驻城市或交易城市分布 | 熵越高越像跨区域品牌 |
| 地址/终端分散度 | 地址、终端、收单信息的差异 | 分散度越高越像多门店 |
| 客群邻域差异 | 同名商户各自 top 邻居集合的差异 | 差异越高越应拆分 |
| 社区分散度 | 预建图后同名商户落入的社区数量 | 多社区分布说明不是单店 |
| 时段画像一致性 | 各门店营业时段是否近似 | 一致但地理分散，常见于连锁 |

品牌识别输出三类结果：

- **单店名称**：同名数据可合并为一个门店节点。
- **连锁品牌**：同名数据必须拆成多个门店节点，并挂同一个 `brand_id`。
- **疑似总部/线上清算名**：保留为灰区商户，后续边权折扣并进入人工复核。

这里的判断应宁可多拆，不要误合并。错误拆分只会让同一门店被多个节点表达，后续仍可通过强共现重新靠近；错误合并会在 PMI 前破坏节点语义，后续很难修复。

## 三、门店实体拆分

门店实体拆分的目标是生成 `merchant_node_id`。推荐按证据强弱分层：

### 3.1 强证据拆分

存在以下字段时，直接形成门店节点：

- 可靠门店 ID、POI ID、终端 ID。
- 标准化地址或经纬度。
- 明确分店名、商场名、街道路名。
- 城市字段或可由持卡人常驻城市稳定反推的经营城市。

节点可以表示为：

```plain
merchant_node_id = hash(brand_id, store_hint, city_id, address_id, terminal_id)
```

其中缺失字段不参与拼接，但必须保留 `store_evidence` 说明实体依据。

### 3.2 弱证据拆分

缺少地址和终端字段时，使用交易网络拆分同名簇：

1. 对同一 `brand_id` 下的原始商户号分别计算客户集合、常驻城市分布和 top 共现邻居。
2. 若两个原始商户号的客户集合重叠低、top 邻居重叠低、常驻城市分布差异明显，则拆成不同门店。
3. 若两个原始商户号高度共享客户和邻居，且时段画像一致，则保留为同一门店的多商户号候选。

弱证据拆分不追求一次完全正确，而是避免把明显不同地点的同名店合并。低置信实体在建图时参与，但边权要乘以实体置信度。

## 四、门店级 PMI/SPPMI

PMI 的计算对象从原来的商户名称调整为 `merchant_node_id`：

$$
C(i,j)=\sum_u s_u(i,j)
$$

其中 $i,j$ 是门店节点，不是名称。边际量也按门店节点计算：

$$
C(i)=\sum_{j\ne i} C(i,j), \qquad T=\sum_{i<j} C(i,j)
$$

门店级 PMI 为：

$$
\mathrm{PMI}_{store}(i,j)=\log \frac{C(i,j)\cdot T}{C(i)\cdot C(j)}
$$

再沿用原方案的最小支持度、CDS 平滑、SPPMI 平移和显著性检验：

$$
\mathrm{SPPMI}_{store}(i,j)=\max(\mathrm{PMI}_{store}(i,j)-\log k,\ 0)
$$

这一步的关键变化不是公式，而是节点语义。只要节点已经拆到门店级，连锁品牌的不同门店就不会共享同一个边际量，也不会把多个商圈的局部强共现混成一个超级节点。

## 五、品牌感知边权修正

门店级 SPPMI 后，新增品牌级风险修正。定义：

- $B(i)$：门店 $i$ 的品牌。
- $R_B$：品牌 $B$ 的连锁风险分。
- $D_B$：品牌 $B$ 的社区分散度或城市分布熵。
- $q_i$：门店实体置信度。

对边权做乘法修正：

$$
w(i,j)=\mathrm{SPPMI}_{store}(i,j)\cdot q_i\cdot q_j\cdot g(i,j)
$$

其中 $g(i,j)$ 是品牌惩罚项：

$$
g(i,j)=
\begin{cases}
\gamma_{same}, & B(i)=B(j)\ \text{且品牌为高风险连锁} \\
\gamma_{chain}, & B(i)\ne B(j)\ \text{且至少一端为高风险连锁} \\
1, & \text{其他情况}
\end{cases}
$$

含义如下：

- 同一高风险品牌的门店之间不应因为名称相同获得额外信任，边权要降权。
- 高风险连锁与其他商户的边仍可保留，但不应主导社区发现。
- 低置信门店实体的边权要降权，避免错误拆分或总部清算名污染图。

参数不在文档中固定，需通过实验记录保存完整快照。首轮可按强弱两档实验比较，例如轻度惩罚和重度惩罚各跑一次，观察连锁品牌导致的社区粘连是否下降。

## 六、互为 top-k 的品牌约束

原方案使用互为 top-k 过滤残留 hub。新方案在此基础上增加品牌约束：

1. 每个门店的 top-k 邻居先按修正后边权 $w(i,j)$ 排序。
2. 对高风险连锁品牌，限制同一 `brand_id` 在一个门店 top-k 中的占比。
3. 同品牌边只能作为辅助边，不参与锚点中心性加分。
4. 若某门店的 top-k 邻居分散到多个城市或多个社区，标记为品牌桥接风险。

这样做的目的不是删除连锁门店，而是防止品牌自身的全国性或区域性分布变成社区发现的主信号。

## 七、迭代清洗新增品牌桥接识别

原方案用参与系数 $P_i$ 清洗线上 hub：

$$
P_i = 1 - \sum_s \left(\frac{k_{is}}{k_i}\right)^2
$$

新方案增加品牌级参与系数：

$$
P_B = 1 - \sum_s \left(\frac{k_{Bs}}{k_B}\right)^2
$$

其中 $k_B$ 是品牌 $B$ 所有门店的总连接数，$k_{Bs}$ 是品牌 $B$ 连向社区 $s$ 的连接数。

清洗规则调整为：

- 单个门店 $P_i$ 高且度数高：按原方案识别为桥接节点，移除或降权后重跑 Leiden。
- 品牌 $P_B$ 高且覆盖社区多：识别为品牌桥接，对该品牌所有门店的跨社区边统一降权。
- 品牌内多数门店都只连接本地社区：保留门店，不剔除品牌。
- 少数门店异常连接多个社区：只处理异常门店，不惩罚整个品牌。

品牌级清洗可以防止一种常见误判：单个连锁门店看起来并不夸张，但品牌整体在多个社区里反复出现，导致社区之间被系统性粘连。

## 八、锚点选择的连锁约束

原方案锚点分为：

$$
\text{AnchorScore}(m)=c(m)\cdot(1-P_m)\cdot\text{stab}(m)\cdot(1+\lambda r(m))
$$

新方案增加连锁惩罚：

$$
\text{AnchorScore}_{chain}(m)=\text{AnchorScore}(m)\cdot h(m)
$$

其中：

$$
h(m)=
\begin{cases}
\eta, & m\ \text{属于高风险连锁品牌} \\
1, & \text{其他情况}
\end{cases}
$$

锚点选择规则同步调整：

- 高风险连锁门店默认不作为第一锚点。
- 带明确分店名、地址可靠、且社区内外漏低的连锁门店可以作为辅助锚点。
- 同一商圈内同一品牌的锚点数量应设上限。
- 锚点集合必须包含非连锁或低连锁风险商户，避免商圈身份被单一品牌绑定。

连锁门店的价值更适合用于质量校验：同一商圈内的连锁门店若地址邻近、社区一致，说明商圈划分可信；如果同一品牌门店把多个社区连成一片，则说明建图仍有粘连风险。

## 九、质量校验与实验记录

每次初始构建实验除保留原方案统计外，新增连锁商户专项统计：

| 指标 | 含义 |
| --- | --- |
| 同名品牌总数 | `brand_id` 数量 |
| 高风险连锁品牌数 | 被识别为连锁的品牌数 |
| 连锁门店节点数 | 高风险品牌下的 `merchant_node_id` 数量 |
| 最大同名门店数 | 单个品牌下最多门店数 |
| 门店实体低置信数量 | `entity_confidence` 低于阈值的节点数 |
| 连锁相关原始边数 | 至少一端为连锁门店的边数 |
| 连锁相关 SPPMI 保留边数 | PMI 后仍保留的连锁边数 |
| 品牌惩罚后保留边数 | 品牌修正后仍保留的连锁边数 |
| 品牌桥接清洗边数 | 迭代清洗中被降权或移除的品牌边数 |
| 可疑社区数 | 连锁占比过高或同一品牌跨社区粘连的社区数 |

自动分析必须新增以下结论：

- 连锁边在最小支持度、SPPMI、互为 top-k、品牌惩罚、迭代清洗各阶段的保留率。
- 商户损失最大的阶段是否由连锁惩罚导致。
- Top 连锁品牌是否覆盖多个社区。
- 是否存在单一品牌占比过高的社区。
- 是否存在同一 `brand_id` 下门店被错误合并或明显过度拆分的迹象。

这些统计需要写入 `docs/experiments.md`，并与原有实验记录的参数快照放在一起，保证可以复现实验。

## 十、推荐验证方式

新方案上线前至少跑三组对比实验：

| 实验 | 节点粒度 | 品牌修正 | 目的 |
| --- | --- | --- | --- |
| 基线 | 原商户名称或原方案节点 | 无 | 复现当前问题 |
| 实体化 | 门店级节点 | 无 | 验证仅修正节点粒度的收益 |
| 实体化 + 品牌约束 | 门店级节点 | 有 | 验证连锁粘连是否进一步下降 |

重点观察：

- 商圈数量是否从异常偏少恢复到合理范围。
- 大社区是否被拆开。
- 高风险连锁品牌在社区间的参与系数是否下降。
- 有效社区覆盖率是否保持稳定。
- 锚点候选是否从高客流连锁转向更稳定的本地核心商户。

## 十一、落地优先级

第一阶段只做最关键的修正：

1. 禁止直接用商户名称作为图节点。
2. 新增 `merchant_node_id` 和 `brand_id` 两层实体。
3. PMI、SPPMI、top-k、Leiden 全部使用 `merchant_node_id`。
4. 实验记录新增连锁品牌统计。

第二阶段再加入品牌感知边权修正：

1. 计算品牌连锁风险分。
2. 对高风险品牌边降权。
3. 增加品牌级参与系数。
4. 在锚点选择中降低高风险连锁权重。

第三阶段处理弱证据实体拆分：

1. 用客户集合、top 邻居和常驻城市分布拆分同名簇。
2. 对低置信实体进入人工复核池。
3. 建立同一物理门店多商户号的合并建议。

## 总结

原 PMI 方案的问题不在于 PMI 公式本身，而在于图节点可能被错误定义为“商户名称”。当多个真实门店共享同一名称时，PMI 面对的是已经合并后的超级节点，无法再恢复地点差异。

改进方案的关键是把“名称”从图节点中剥离出来：

- `merchant_node_id` 负责表达门店实体。
- `brand_id` 负责表达连锁品牌。
- PMI 只在门店级节点上计算。
- 品牌信息只用于识别、惩罚、清洗和质量校验。

这样既保留了连锁门店作为本地商圈成员的有效信号，又避免同一品牌跨地点、跨商圈把社区错误粘连。
