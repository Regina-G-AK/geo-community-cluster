# 基于信用卡交易数据的商圈构建与增量维护算法设计
## 文档目的
本文档面向"无法获取商户地理坐标、仅凭交易共现重建线下商圈"的场景,给出一套可落地的完整算法体系。整体设计遵循一个核心原则:

> **聚类只做一次冷启动,经人工修正后固定;之后把问题从"无监督聚类"转化为"有监督归属",新商户逐个判定进入,辅以新商圈发现旁路和定期维护。**
>

这样做的三个理由:其一,聚类不可能一次得到完美商圈,人工介入不可避免,而人工修正过的成员关系本身就是高质量标注数据,可反哺归属模型;其二,商户持续新增,每次全量重聚类会导致商圈 ID 漂移,破坏营销活动、报表、客群标签的跨期对齐;其三,固定的商圈 ID 带来稳定性和可解释性。

文档包含三套算法:

1. **算法一:商圈初始构建**(冷启动,无监督聚类)
2. **算法二:新商户增量归属**(日常运行的主路径)
3. **算法三:商圈更新与维护**(健康度监控、存量重检、坐标反推)

## 第一章 算法一:商圈初始构建(冷启动聚类)
本算法只在系统冷启动时运行一次,产出初始商圈供人工修正后定稿。核心思想:**用交易共现重建空间邻近,关键挑战是线上商户像"停用词"一样和谁都共现,会把多个商圈粘连在一起。** 解决之道不是追求 100% 识别线上商户,而是让图的构建方式本身对漏网线上商户免疫。

> **本章的最终目标其实是锚点。** 初始构建产出的不只是"一堆商圈成员",更关键的是**每个商圈的锚点商户集合 **$A_s$(见 1.5)。锚点一旦人工确认,商圈身份就被钉死;其余成员都可以由算法二的增量归属重新放入、由算法三定期重检。所以整条链路可以理解为:**一套为"确定锚点"服务的流程。**
>

算法一的步骤顺序:**线上识别(先净化数据)→ 交易对生成 → PMI 计算与建图 → 迭代清洗 + 社区发现 → 锚点确定 → 质量校验。**

### 1.1 第一步:线上商户识别(交易特征粗筛)
把线上商户的剔除放在最前面,先净化原始数据再建图,从源头减少粘连。这一步只用**原始交易就能算出的特征**(图结构特征要到 1.4 才有图可用,届时再补一道):

+ **城市分布熵**(判别力最强):按持卡人常驻城市(发卡地、账单地址、或其线下交易的众数城市)把交易归到不同城市。线下商户只在一个城市高频出现;一个商户在多个城市都活跃,几乎必是线上。用各城市交易占比算香农熵,熵越高越像线上。
+ **不可能旅行**:同一持卡人前后 ≤10 分钟的交易对中,若某商户频繁与地理上不可能连续到达的商户配对,它是线上。
+ **时段分布**:凌晨 0~6 点交易占比。线下受营业时间约束,线上不受。
+ **MCC、商户名规则、终端/渠道字段**:叠加已有规则(MCC 落在电商/航旅/游戏类、商户名含"网络科技""支付"等)。

把已有人工标注当训练样本,用这些特征训一个 GBDT 分类器,输出线上概率:

+ 高于阈值 → 直接剔除,不参与后续建图;
+ 中间灰色地带 → 不剔除,但在 1.2 生成交易对时给它的边权打折,避免误杀线下商户;
+ 低于阈值 → 正常参与。

**为什么只是粗筛、不是终筛**:交易特征抓不全,尤其体量不大的线上商户。所以这一步只求"宁可漏过、不要误杀"。真正兜底的是 PMI(1.3)和图结构清洗(1.4)——它们让漏网的线上商户即使留在图里也长不出强边、并在聚类后被参与系数揪出来。**识别只是第一道闸,不要把成败押在它身上。**

### 1.2 第二步:交易对的生成
本步把净化后的交易转成带权的**商户对共现强度 **$C(a,b)$,作为建图原料,分三小步。

**(1) 从交易到"到访"事件。** 同一持卡人 $u$ 在同一商户 $m$ 短时间内的多笔交易(分单、补刷)只代表一次空间到达,合并为一个**到访事件** $(u, m, t)$:把 $u$ 在 $m$ 的交易按时间排序,间隔小于 **30 分钟**的相邻交易并入同一次到访,$t$ 取首笔时间。同时剔除退款冲正、1.1 已判定的线上商户,以及单日到访商户数异常多(如 > 30)的卡——这类卡多为异常用卡或测试卡,会以 $O(k^2)$ 的速度制造垃圾共现对。

**(2) 交易对的定义。** 对每个持卡人,将到访序列按时间排序。两次到访 $(m_i, t_i)$、$(m_j, t_j)$ 构成一个**交易对**,当且仅当:

$$ m_i \neq m_j, \qquad 0 < |t_i - t_j| \leq \Delta T $$

商户对无序,$(a,b)$ 与 $(b,a)$ 视为同一对。$\Delta T$ 取 2 小时,对应同城步行/短途移动的尺度——这个尺度下"先后光顾两家店"最能反映物理邻近。给每个交易对一个**时间衰减权重**,让间隔越短信号越强:

$$ \kappa = \exp\left(-\frac{|t_i - t_j|}{\tau}\right), \qquad \tau \approx 1\ \text{小时} $$

**公式说明**:指数衰减。间隔 0 时 $\kappa=1$;间隔等于 $\tau$ 时 $\kappa\approx 0.37$;越大越趋近 0。两次刷卡挨得越近,越像"在一个商圈里连续逛",邻近证据越强。

**(3) 用户级聚合与去重(防刷量的关键)。** **先在用户内聚合,再跨用户求和**,保证单个持卡人对一条边的贡献有上界。用户 $u$ 对 $(a,b)$ 的贡献,取其所有 $(a,b)$ 交易对中权重的**最大值**:

$$s_u(a,b) = \max_{u \text{ 的所有 } (a,b) \text{ 交易对}} \kappa \in (0,1]$$

一个人无论往返多少次,贡献封顶为 1。跨用户求和得边的共现强度:

$$C(a,b) = \sum_u s_u(a,b) $$

**公式说明**:当 $\kappa=1$ 时,$C(a,b)$ 就是"窗口内同时光顾过 $a$、$b$ 的去重持卡人数"。**边的强度由人群广度决定,而非少数人的频次**——真邻近会有很多不同人先后光顾,一个人反复往返不构成商圈证据。若 1.1 把某商户判为灰色地带,在此给它参与的 $s_u$ 乘一个 <1 的折扣系数。本步的输出是全体边的共现强度集合 $\{C(a,b)\}$。

### 1.3 第三步:PMI 计算与建图
本步把原始共现强度 $C(a,b)$ 转成**对线上 hub 免疫的边权**,并稀疏化成图。

**(1) PMI(免疫线上 hub 的核心)。** 记全图总量与边际量:

$$T = \sum_{a<b} C(a,b), \qquad C(a) = \sum_{b \neq a} C(a,b) $$

点互信息(略去对排序无影响的常数项):

$$ \mathrm{PMI}(a,b) = \log \frac{C(a,b)\cdot T}{C(a)\cdot C(b)} = \log \frac{C(a,b)}{E(a,b)}, \qquad E(a,b) = \frac{C(a)\,C(b)}{T} $$

**为什么 PMI 能压制线上商户——务必理解透。** $E(a,b)$ 是"假如 $a$、$b$ 的客户互相独立、纯随机搭配,期望产生的共现量"。于是 PMI 衡量"实际共现超出随机预期的倍数(的对数)":

+ 漏网的线上巨头 $h$,客户近似全量持卡人的随机抽样,对任意 $b$ 都有 $C(h,b)\approx E(h,b)$,故 $\mathrm{PMI}(h,b)\approx \log 1 = 0$。**即使没被 1.1 识别出来,它在图里也长不出强边。**
+ 真实商圈内的两家店,实际共现是随机期望的几十上百倍,$\mathrm{PMI}$ 显著为正。

PMI 做了"除以期望"的归一化,把体量因素消掉,只留下"超额关联"这个空间邻近的本质信号。**这是对抗 hub 污染最重要的防线,远比 1.1 的人工/规则识别可靠。**

**(2) 三个必要修正(防低频虚高)。** 裸 PMI 会让两个各被光顾几次、碰巧共现一次的小商户排到最前。三个修正叠加:

+ **最小支持度(硬门槛)**:$C(a,b) \geq n_{\min}$(当前取 3),低于此一律不建边。
+ **上下文分布平滑(CDS)**:用 $P_\alpha(b) = \frac{C(b)^\alpha}{\sum_{b'} C(b')^\alpha}$($\alpha=0.75$)替换分母边际。幂次 <1 相对抬高低频商户的边际概率,压低其虚高 PMI;0.75 是词向量文献的经验值,直接沿用。
+ **平移正截断(SPPMI)**:$\mathrm{SPPMI}(a,b) = \max(\mathrm{PMI}(a,b) - \log k,\ 0)$,$k$ 建议 3。减 $\log k$ 设一个显著性门槛(只保留超随机期望 $k$ 倍以上的边),取 max 与 0 丢弃"比随机还稀疏"的负 PMI 边。

**(可选)显著性检验**:独立假设下 $C(a,b)$ 近似泊松,$z(a,b) = (C(a,b)-E(a,b))/\sqrt{E(a,b)}$,要求 $z\ge z_{\min}$(如 3)。PMI 衡量关联强度、$z$ 衡量置信度,二者互补——小商户对强度高但置信度不足,hub 对样本大但强度为零,双门槛同时滤掉两类噪声。

**(3) 稀疏化成图。** 对每个商户按 $\mathrm{SPPMI}$ 取 top-k 边($k\approx 10\sim20$),并用**互为 k 近邻**的严格版:边 $(a,b)$ 保留当且仅当 $b$ 在 $a$ 的 top-k 中 **且** $a$ 在 $b$ 的 top-k 中。这是对残留 hub 的第二重保险——线上商户即便挤进某些小商户的 top-k,自己的 top-k 早被海量候选稀释,反向不成立,这条边就建不起来。最终图:节点为商户,边权为 $\mathrm{SPPMI}$,经支持度、(可选)显著性、互近邻三重过滤。

### 1.4 第四步:迭代清洗 + 社区发现
在稀疏图上用 **Leiden 算法**(比 Louvain 稳定,不产生不连通社区)做社区发现,得到初步商圈划分。然后用**图结构特征**做线上识别的第二道(也就是 1.1 里因"需要图"而推迟的那部分),对每个节点算参与系数:

$$P_i = 1 - \sum_s \left(\frac{k_{is}}{k_i}\right)^2 $$

$k_i$ 为节点 $i$ 总度数,$k_{is}$ 为 $i$ 连向社区 $s$ 的边数。

**公式说明**:$P_i$ 衡量一个节点的边"分散到多少个社区"。

+ 线下商户的边几乎全落在自己商圈内,某个 $k_{is}/k_i\approx 1$,其余为 0,$P_i\approx 0$。
+ 漏网线上商户的边均匀散在多个社区,每个 $k_{is}/k_i$ 都很小,平方和很小,$P_i\to 1$。

把高参与系数 + 高度数的节点移除或降权,重新跑 Leiden,**迭代 2~3 轮即收敛**。它们粘合多个商圈的行为本身,就是暴露线上身份的证据——这正是 1.1 用交易特征抓不住、必须靠图结构兜底的那批商户。

Leiden 的 `resolution` 参数控制粒度,可输出粗(区域级)、细(街区/购物中心级)两层,营销时按需选用。本步输出**初始商圈划分**。

### 1.5 第五步:锚点确定(本章的核心产物)
社区划好后,要为每个商圈选出**锚点商户集合 **$A_s$。锚点是商圈的"身份证":人工只需确认锚点,商圈就被钉死,其余成员交给算法二/三动态维护。

**为什么不能用"销量最大"选锚点。** 高销量商户常常恰恰是最差的锚点:超市、加油站、连锁餐饮这类高客流商户,顾客来自四面八方,在共现图里是典型的近 hub,既不代表某个特定的小空间,还容易跨商圈连接。**销量大 ≠ 在图里中心、≠ 空间上有代表性。** 锚点要的是"在本商圈内核心、对外不外漏、且稳定",这要用图结构来判定。

锚点应同时满足四个条件,综合成一个打分。在商圈 $s$ 的**诱导子图** $G_s$(只保留两端都在 $M_s$ 内的边,权为 $\mathrm{SPPMI}$)上计算:

**(1) 社区内中心性 ** $c(m)$(越高越好)。推荐在 $G_s$ 上跑 **加权 PageRank**:

$$ c(m) = \frac{1-\beta}{|M_s|} + \beta \sum_{b \to m} \frac{w(b,m)}{\sum_{b'} w(b,b')}\, c(b) $$

**公式说明**:PageRank 衡量"随机游走在本商圈内部停留在 $m$ 的概率"。它比单纯的度数更好——奖励的是"和其他核心商户相连",而不只是"连了很多店"。简化版可直接用**社区内加权度** $c(m)=\sum_{b\in M_s} w(m,b)$,工程上够用。

**(2) 低参与系数 **$P_m$(越低越好,直接复用 1.4 的 $P_m$)。锚点的边应几乎全在商圈内部,$P_m\approx 0$;边外漏多的是边界/桥接商户,不适合当锚点。

**(3) 跨期稳定性 **$\text{stab}(m)$(越高越好)。用最近 $W$ 个滚动窗(如 3 个月各一窗)分别算 $c(m)$,锚点应在每个窗里都稳居高位。可用 $\text{stab}(m) = \overline{c}(m) / (1 + \text{std}(c(m)))$——均值高、波动小者得分高。这能排除昙花一现的网红店,保证锚点像"地标"一样稳定。

**(4) 坐标可靠性 **$r(m)$(加分项)。优先选有可靠坐标的商户(带分店名的连锁、地址核验过的商户),因为锚点要充当算法二地理打分 $\text{Score}_{\text{geo}}$ 的几何参照系 $A_s$、并定义带宽 $\sigma_s$。

综合锚点分:

$$\text{AnchorScore}(m) = c(m)\,\cdot\,(1 - P_m)\,\cdot\,\text{stab}(m)\,\cdot\,(1 + \lambda\, r(m)) $$

($\lambda$ 为坐标加分系数,如 0.5。)按此分降序,为每个商圈选 **top-N** 作候选锚点($N$ 随商圈大小缩放,下限 3、上限按规模放大),提交人工确认。

**两个工程要点:**

+ **锚点要"成组"而非"独一",且地理上分散。** 单个锚点不足以锚定狭长街道型商圈。在高分候选里,若有坐标,应优先选**地理上彼此拉开距离**的一组(类似最远点采样),让 $A_s$ 覆盖商圈的空间范围——否则锚点都挤在街道一头,算法二的"到锚点最近距离"会误判另一头的商户。
+ **锚点决定身份,但全体成员仍是投票上下文。** 注意算法二的图打分用的是 $x$ 的所有邻居及其标签(锚点票权加倍),不是只看锚点。所以非锚点成员不会被丢弃,它们持续充当 kNN 投票邻居。人工只维护锚点这一小撮高置信集合,其余成员由算法自动归入与重检——这正是你所理解的运营模型,且成立的前提就是"锚点身份稳定 + 成员可自动重算"。

### 1.6 第六步:质量校验
+ **连锁店锚点核验**:商户名带分店名的连锁(如"星巴克(国贸店)")是免费的地理参照。同一商圈内的此类锚点若地址确实邻近,商圈质量就有了客观验证,还能顺手给商圈打地理标签。
+ **时段一致性**:同一商圈商户高峰时段应相似(写字楼商圈午高峰、夜市商圈晚高峰),否则提示该商圈可能被错误合并。

### 1.7 算法一整体流程
```plain
原始交易
  → 【第一步】线上识别(交易特征 GBDT 粗筛:城市熵/不可能旅行/时段/MCC)
        剔除高分;灰色地带降权
  → 按城市切分子图              ← 本身就是最强的线上过滤器
  → 【第二步】交易对生成
        到访合并(30min) → 滑窗配对(ΔT=2h, 衰减 κ)
        → 用户级 max 封顶 → 跨用户求和 → C(a,b)
  → 【第三步】PMI 计算与建图
        PMI → CDS 平滑 → SPPMI → 支持度/显著性/互近邻三重过滤 → 稀疏图
  → 【第四步】迭代清洗 + 社区发现
        Leiden → 参与系数揪出图结构上的残留 hub → 迭代 2~3 轮 → 初始商圈
  → 【第五步】锚点确定
        诱导子图算 PageRank·(1-P)·稳定性·坐标加分 → top-N 候选锚点
  → 【第六步】质量校验(连锁锚点 + 时段一致性)
  → 初始商圈 + 候选锚点
  → 【人工修正:合并/分割/确认锚点】
  → 定稿(锚点钉死商圈身份),进入固定层
```

> **重要实施提示**:整条链路在**按城市切分后的子图**上独立运行,$T$、$C(a)$ 等统计量都在城市内计算,不要全国混算——同名商户跨城市、线下商户只在单城市活跃的特性,正是城市切分能成为最强线上过滤器的原因。计算瓶颈在第二步逐用户滑窗配对,复杂度 $\sum_u\sum_{\text{窗口}}k^2$,按"持卡人 × 日期"分片天然可并行。

## 第二章 算法二:新商户增量归属
初始商圈定稿后,系统进入日常运行。问题已从"无监督聚类"转化为"有监督归属":**把新商户逐个判定进入已有商圈。** 但纯增量有一个结构性盲点必须正视:

> 它只会往旧商圈里塞商户,**永远发现不了新商圈**。新开业的购物中心、新兴街区,其商户彼此强连接却与任何旧商圈弱连接。增量逻辑要么把它们错误吸附到最近的旧商圈,要么全部悬空。
>

因此设计中必须有一条"新商圈发现"旁路(见 2.5)。

### 2.1 商圈档案(固定层)
人工定稿后,每个商圈 $s$ 维护一份档案:

+ **成员集合** $M_s$ 及每个成员的归属置信度(人工确认 > 高分自动归入 > 低分存疑);
+ **锚点子集** $A_s\subset M_s$:由 1.5 的锚点分选出、经人工确认的核心商户(高社区内中心性、低参与系数、跨期稳定、优先有坐标),是商圈身份的载体和后续打分的几何参照系。**人工日常维护的就是这个集合;** 非锚点成员由增量归属自动放入、由算法三定期重检;
+ **客群摘要**:商圈活跃持卡人集合的 MinHash / HyperLogLog sketch(避免存全量集合);
+ **地理轮廓**:用有坐标成员算质心和地理尺度 $\sigma_s$(锚点点间距中位数),坐标够多时可算凸包。

> **关键分层设计:商圈标签固定,但共现统计量滚动。** $C(a,b)$、$C(a)$、$T$ 基于滚动窗口(如最近 6 个月交易)持续重算——商户的邻近关系会随客流变化,用过期统计给新商户打分会失真。**固定的是"谁属于哪个商圈"这个映射,不是底层的图。**
>

### 2.2 观察池机制
新商户 $x$ 上线后先进入**观察池**,积累到最低证据量(如 **4~8 周** 且去重持卡人 ≥ 某阈值)才参与判定。证据不足就强行判定,等于用噪声做决策。

### 2.3 三类归属分数
判定时对每个候选商圈 $s$ 计算三类分数。

**(1) 图分数——加权 kNN 投票**

用算法一同一套管道(到访合并、用户级封顶、SPPMI、互近邻)计算 $x$ 与存量商户的边,取 $x$ 的 top-k 邻居 $N_k(x)$,按邻居的商圈标签加权投票:

$$\text{Score}_{\text{graph}}(x, s) = \frac{\displaystyle\sum_{b \in N_k(x),\ \ell(b)=s} w(x,b)}{\displaystyle\sum_{b \in N_k(x)} w(x,b)}$$

其中 $w$ 为 $\mathrm{SPPMI}$ 边权。

**公式说明**:分子是 $x$ 的邻居中"属于商圈 $s$"的那些边权之和,分母是全部邻居边权之和。所以这个分数就是"$x$ 的邻近关系里,有多大比例指向商圈 $s$"。它天然归一化(各商圈分数之和为 1),且继承了 PMI 对线上 hub 的免疫。可让锚点商户的票权乘一个系数(如 1.5),因为它们标签最可靠。

**(2) 地理分数**(若 $x$ 有坐标)

$$ \text{Score}_{\text{geo}}(x, s) = \exp\left(-\frac{d(x, A_s)^2}{2\sigma_s^2}\right) $$

**公式说明**:这是一个高斯核。$d(x,A_s)$ 是 $x$ 到商圈 $s$ **锚点集的最近距离**(不是到质心的距离——商圈形状常是狭长街道,质心可能落在街区外,最近距离更稳健)。距离为 0 时分数为 1,距离越大分数越快趋近 0。带宽用各商圈自己的 $\sigma_s$,这样大商圈和小商圈的判定尺度会自动不同。

**(3) 客群分数**

$x$ 的持卡人集合与商圈客群 sketch 的 Jaccard 相似度:

$$ \text{Score}_{\text{cust}}(x, s) = \frac{|U_x \cap U_s|}{|U_x \cup U_s|} $$

($U_x$、$U_s$ 用 MinHash 估计,无需存全量集合。)这是图分数的低配冗余(共现本质上就是客群重叠加时间约束),但在 $x$ 交易稀疏、共现边还建不起来时,能提前给出弱信号。

### 2.4 分数融合与三态判定
**融合**。冷启动期用加权和:

$$ \text{Score}(x,s) = 0.6\,\text{Score}_{\text{graph}} + 0.3\,\text{Score}_{\text{geo}} + 0.1\,\text{Score}_{\text{cust}} $$

(无坐标时把地理项的权重按比例分摊给另两项。)积累一段时间后,**用初始聚类 + 人工修正的存量成员做训练集**——每个商户的三类分数为特征、归属为标签——训一个逻辑回归或 GBDT 替代手工权重。**这就是把人工标注变成持续复利的监督信号的具体落点。**

**三态判定**(不要二选一)。设 $s_1, s_2$ 为分数最高的两个商圈:

| 决策 | 条件 |
| --- | --- |
| **归入** $s_1$ | $\text{Score}(x,s_1)\ge\theta$ **且** $\text{Score}(x,s_1)-\text{Score}(x,s_2)\ge\delta$ |
| **继续观察** | 证据量不足,或最高分 $<\theta$,留在观察池等下个周期 |
| **送人工** | margin 不足($s_1$、$s_2$ 都很强,可能位于商圈交界);**或** 图分数与地理分数指向不同商圈 |


**说明**:

+ "绝对门槛 $\theta$ + margin $\delta$"双条件,防止"矮子里拔将军"——一个商户和所有商圈都很弱,但总有个最高的,不能就把它归进去。
+ **图地冲突触发人工特别重要**:图说 A、坐标说 B 的商户,要么数据脏,要么是线上漏网,要么坐标是注册地址而非经营地址(连锁品牌清算商户号挂总部地址是高发情况)。无论哪种都值得人看一眼。这让两个信号源**互为校验器**,而不是简单加权后被平均掉。

### 2.5 新商圈发现(旁路)
观察池中长期无法归属的商户,定期(**月度**)单独跑一次局部 Leiden:

+ 若其中出现一个**内部 SPPMI 密集、对外连接稀疏**的团(如 ≥10 个商户,内部边密度显著高于其与任何已有商圈的连接密度),生成"**候选新商圈**"工单提交人工确认;
+ 确认后建档,进入固定层。

这条旁路成本很低(只在残余商户上算),却补上了纯增量方案的结构性盲点。

### 2.6 算法二整体流程
```plain
新商户 x 上线 → 进入观察池
  → 积累证据(4~8 周 & 去重人数达标)
  → 计算三类分数(图 / 地理 / 客群)
  → 融合(初期加权和;后期 GBDT/LR)
  → 三态判定:
       归入 s1   → 写入 M_{s1},更新档案
       继续观察 → 留池等下周期
       送人工    → 人工裁决后写入
  → 月度:对长期悬空商户跑局部 Leiden
       → 发现致密团 → 候选新商圈工单 → 人工确认 → 建档
```

## 第三章 算法三:商圈更新与维护
固定不等于永久。商户会搬迁、倒闭、商户号被复用;商圈会扩张、衰退、彼此融合。需要轻量的维护机制持续纠偏。**注意:所有算法只负责"开工单/给建议",执行权(合并、分割、确认)始终在人。**

### 3.1 商圈健康度监控
对每个商圈滚动计算两个指标。

**内部连接密度**(成员间平均边权):

$$ \rho_s = \frac{\displaystyle\sum_{a,b \in M_s,\ a<b} w(a,b)}{\binom{|M_s|}{2}} $$

**电导**(对外连接占比):

$$ \phi_s = \frac{\displaystyle\sum_{a\in M_s,\ b\notin M_s} w(a,b)}{\displaystyle\sum_{a\in M_s} \sum_{b\ne a} w(a,b)} $$

**公式说明**:$\rho_s$ 高、$\phi_s$ 低,是一个健康商圈应有的形态(内部抱团、对外稀疏)。

+ $\rho_s$ **持续下降** → 商圈在松散化(可能成员里混入了不相关商户,或商圈实际在衰退);
+ $\phi_s$ **持续上升** → 对外连接增多,可能商圈在扩张,或正与邻圈融合。

触发条件命中时,生成人工复核工单,并附算法建议(分裂 / 合并 / 维持)。

### 3.2 存量成员重检
归属判定也会出错。**每季度**对全体成员用最新统计量重打一遍分:

+ 分数跌破阈值的成员列入复核清单。常见原因:店铺搬迁、倒闭后商户号被复用、当初误归。
+ 重检用的是滚动窗口的最新 $C(a,b)$,所以能捕捉到"关系随时间变化"的成员。

> **数据层配套:商户主数据治理。** 商户号复用、同一物理商户挂多个清算号,是增量层被持续污染的根源。建议在数据层单独建一套商户主数据逻辑,做实体归一(把指向同一物理店铺的多个商户号合并、给倒闭复用的号打时间断点),否则上层算法会反复被脏 ID 干扰。
>

### 3.3 坐标反向推断(系统副产品)
随着有坐标商户增多,商圈地理轮廓越来越完整,可**反向推断无坐标商户的近似位置**:

+ 粗粒度:无坐标商户的位置 ≈ 其所属商圈的地理范围;
+ 细粒度:按其最强的若干邻居(有坐标者)做边权加权插值:

$$ \hat{p}(x) = \frac{\displaystyle\sum_{b \in N_k(x),\ b \text{ 有坐标}} w(x,b)\cdot p(b)}{\displaystyle\sum_{b \in N_k(x),\ b \text{ 有坐标}} w(x,b)} $$

其中 $p(b)$ 是 $b$ 的坐标。

**价值**:你们最初的痛点是拿不到商户地理位置。这套系统跑起来后,实际上在用交易数据**逐步重建一张商户地图**。这张地图对选址分析、营销半径设定都有独立价值,是整个体系的一个高价值副产品。

### 3.4 算法三整体流程
```plain
持续滚动(共现统计量按 6 个月窗口刷新)
  ├─ 健康度监控:算 ρ_s、φ_s
  │     → 异常 → 复核工单(附分裂/合并建议) → 人工裁决
  ├─ 季度存量重检:全成员重打分
  │     → 跌破阈值 → 复核清单 → 人工裁决
  │     ↑ 依赖商户主数据治理(实体归一、号复用断点)
  └─ 坐标反推:补全无坐标商户位置 → 商户地图资产
```
